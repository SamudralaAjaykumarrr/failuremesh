# Gate A decision: REVISE

**Mechanism-fit coverage: 10/10 exact-family L0 candidates. Canonical public-incident coverage: 8/10. Gate A: REVISE. Phase 1: NOT AUTHORIZED.** The [canonical baseline](../../company/canonical-baseline-v1.0.md) requires ten public incidents encoded before the next validation step. Mechanism evidence from an injected reproduction, project race analysis, or formal model cannot substitute for an observed incident. The [abstraction-fit review](abstraction-fit.md) still finds no demonstrated model blocker, but that does not waive the incident milestone.

For this audit, a qualifying public incident is a publicly documented real observed operational failure with the defining family mechanism. A project bug counts only when it reports concrete observed operational failure, rather than only a code-path hypothesis or synthetic test. A retrospective can count without a single timestamped trace when it clearly reports real failures and their mechanism; that limitation remains explicit. Production scope is recorded separately where the source does not establish it. Exact mechanism fit does not establish downstream impact or a FailureMesh verdict.

The final targeted pass found a qualifying [Apache Iceberg Kafka Connect production issue](https://github.com/apache/iceberg/issues/16282) for family 10. It reports two production incidents and gives a dated trace for one: file X committed in one snapshot, worker timeout and coordinator shutdown before control-topic offset advancement, replay by a replacement coordinator, and the same file committed in a second snapshot. The reporter's metadata query found duplicate file registration and rows. This is **PROJECT_BUG_WITH_PRODUCTION_OBSERVATION**, not independently audited evidence; the RabbitMQ discussion remains supplementary mechanism analysis. The Iceberg report also describes a zombie coordinator racing after leadership loss, but does not establish a lease/session expiry sequence or a separately described second incident for family 3, so it is not double-counted.

Family 1 remains unqualified. [OpenTofu S3 lockfile issue #4405](https://github.com/opentofu/opentofu/issues/4405) reports a real committed conditional PUT with ambiguous caller outcome and an orphaned lock, but explicitly cannot distinguish SDK retry from a late 412 on the original call and does not show a second committed effect. [Mollie idempotency guidance](https://docs.mollie.com/reference/api-idempotency) and [Stripe idempotency guidance](https://stripe.com/blog/idempotency) are mechanism documentation. Family 3 also remains unqualified: [Kafka KAFKA-2729](https://issues.apache.org/jira/browse/KAFKA-2729) includes production symptoms, but the maintainer presents zombie-controller actions after session expiry as a possible cause, not an observed ordered trace of that incident. The HBase analyses remain exact L0 mechanism evidence. Searches across payments, cloud APIs, object stores, distributed databases, ZooKeeper/Kafka systems, queues, and worker platforms did not establish a stronger qualifying primary source for either gap. This **final incident-search pass is closed**; no further generic incident-search loop is recommended.

The three conceptual reference shapes remain [synchronous external effect](reference-architectures/01-sync-service-external-side-effect.md), [queue/worker delivery](reference-architectures/02-queue-worker-delivery.md), and [distributed dependencies](reference-architectures/03-distributed-service-dependency.md). No FailureMesh reproduction, customer applicability assessment, execution verdict, or portability claim has occurred. Gate A can be reconsidered after qualifying exact-family observed incidents are encoded for families **1 and 3** and the fit review is checked again. This decision preserves the baseline; it is not a baseline change.
