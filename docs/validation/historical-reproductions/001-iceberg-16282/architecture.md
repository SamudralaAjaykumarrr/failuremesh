# Incident architecture and AC

The incident-specific AC is `historical.iceberg-16282@1`, scoped to a local synthetic reference build. It uses the repository's fact shape: value, evidence, source, scope, quality, sensitivity, conflict, and stale status. Its causal facts cover durable table commit, separate control consumption, event replay, commit-before-offset gap, shutdown in the gap, recovery from committed offset, append-only/no equality deletes, non-idempotent registration, and observability of file identity, snapshots, and offset. Their quality is `reported`: they are directly present in the public reporter's account, but are not independently verified upstream facts. The local PostgreSQL fixture supplies direct execution observation separately. A missing, stale, conflicting, or insufficient causal fact yields UNKNOWN. Evidenced absence yields NOT_APPLICABLE. Catalog type is a visible non-causal UNKNOWN with REST/JDBC conflict and does not alter applicability.

The fixture has coordinator-C1 and coordinator-C2 as sequential logical actors, one synthetic `DATA_WRITTEN` event `data-written-X` at synthetic offset 7, `file-X`, `snapshot-S1`, `snapshot-S2`, a durable control position initially and finally at 6, PostgreSQL snapshots/file registrations, consumption records, offset-history records, and an ordered trace. Offset 7 is an arbitrary local identifier, not an incident fact. The table append path has no file-identity uniqueness constraint across snapshots. Safety ceiling is level 1; one event, eleven steps, two registrations, no broker, Iceberg runtime, catalog, or external storage.
