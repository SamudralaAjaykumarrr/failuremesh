# Vision and claim boundary

The authoritative [baseline](company/canonical-baseline-v1.0.md) defines FailureMesh as Portable Reliability Intelligence: collective memory of software failure mechanisms that can be checked against another architecture and tested with executable evidence. Customer value follows KNOWLEDGE → APPLICABILITY → EXECUTION → EVIDENCE. The product must preserve shared failure knowledge, architecture applicability, automatic adaptation, and executable evidence together.

The initial wedge is backend, platform, and SRE teams with distributed services, PostgreSQL, queues, workers, retries, leases, idempotency, external APIs, and concurrency. The moat hypothesized in the baseline is a verified PFC corpus, architecture-to-failure mappings, cross-system execution evidence, adapters, privacy-preserving contributions, and remediation evidence across architecture families. These are strategy hypotheses, not validation results.

FailureMesh reports a scoped observed exposure or resilience result, or `UNKNOWN`. It does not prove a system universally safe, promise an outage cannot happen, or claim AI finds every issue. No customer adoption, external incident reproduction, expert interview, pilot, or payment is asserted by these Phase 0 documents.
