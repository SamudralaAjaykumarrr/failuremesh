# Testing and evidence strategy

Phase 0 is complete; Gate A remains REVISE. The bounded Phase 1 synthetic prototype has Go packages and PostgreSQL integration tests. Run `python3 scripts/validate_gate_a.py`, `python3 scripts/check_markdown_links.py`, and `python3 -B -m unittest discover -s scripts/tests -v` for repository checks. CI runs gofmt, `go mod verify`, `go vet ./...`, `go test ./...`, `go test -race ./...`, and a committed-whitespace check with a synthetic PostgreSQL service. These checks guard document structure, recorded checkpoint consistency, links, tooling behavior, and the bounded reference execution. They do not establish the factual truth of source incidents, customer applicability, or portability.

The Gate A validator checks the exact bytes of `docs/company/canonical-baseline-v1.0.md` against a reviewed SHA-256 constant in `scripts/validate_gate_a.py`. A digest pass is byte integrity, not semantic approval. Change that constant only after an explicitly approved **PROPOSED BASELINE CHANGE** under the baseline's change rule; then compute the new digest from the approved file with `sha256sum docs/company/canonical-baseline-v1.0.md`, update the constant deliberately, review the complete baseline diff, and rerun the repository checks. Ordinary documentation edits never update it automatically.

Future tests must distinguish contract parsing/version rejection, deterministic applicability truth tables, safety-denial behavior, adapter causal fidelity, causally synchronized fault placement, evidence completeness/integrity, and verdict rules. For Phase 1, a run/logical-operation keyed simulator barrier must prove durable effect and authoritative commit evidence before response loss and before caller success; tests must reject pre-commit loss, reproduce placement with identical controlled inputs, and verify reset/isolation. Wall-clock sleeps cannot place the fault. Use deterministic reference fixtures and record seeds or scheduler controls when unavoidable. Negative tests must cover missing and conflicting AC facts, missing post-commit confirmation, missing retry observation, incomplete effect ledger, aborts, and stale evidence: each must produce `UNKNOWN` rather than an unwarranted result.

Phase 1 acceptance is an end-to-end two-run demonstration under a pinned build and environment. The vulnerable run must show one logical operation, a committed provider effect, lost response, retry, and two distinct effects, producing `EXPOSED` and a replayable counterexample. After idempotency/reconciliation remediation, the same declared experiment space must show retries with exactly one logical effect and complete observations, producing a scoped `PROVEN_RESILIENT` bundle. Repeatability should be checked across clean resets; failed or flaky repeats are `UNKNOWN` until investigated. See [Phase 1](phases/phase-1-first-vertical-slice.md).
