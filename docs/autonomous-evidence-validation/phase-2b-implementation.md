# Phase 2B local corpus implementation

Implementation decisions, subordinate to the [approved design](phase-2b-curated-corpus.md).

The implementation is a local metadata register. Real corpus collection is not implemented. No crawler, internet retrieval, natural transfer results, architecture packets, new PFC, Gate A changes, customer execution or production execution.

## Decisions pinned before implementation

`corpus-v1` and `corpus-manifest-v1` use `corpus-go-json-v1`: Go struct declaration order, explicit fields including null pointers, UTF-8, integer-only numeric fields, Go JSON escaping, no trailing newline. Strict decode compares exact re-encoded bytes; duplicate/unknown keys, omitted fields, alternative escapes and whitespace are refused. Set fields sort lexicographically by stable identity; duplicates are rejected. Histories use ledger order. SHA-256 digests use the unchanged Phase 2A `{algorithm,hex}` representation and hash exact payload bytes, with the digest outside the payload. This is not general JSON canonicalization.

Hard ceilings: object and manifest 4 MiB; source references per candidate 64; relations 4096; exposure objects 8192; closure objects 16384; closure bytes 64 MiB; complete authoritative store files 65536 and bytes 256 MiB. Sequence/revision maximum 65535. Input over a limit is refused without truncation.

Supported environment: Linux, trusted local root and ancestors, regular files/directories, cooperating writers. Reject symlinks at every path component, nonregular objects, and known network/pseudo filesystems; explicitly allow ext4, XFS, Btrfs, tmpfs and overlayfs. Local administrators remain trusted. No distributed-filesystem or hostile-administrator correctness claim.

One advisory `flock` covers read/validate/expected-head/publication. Exclusive temporary files are file-synced and atomically hard-linked to immutable final names (no-replace publication, as in Phase 2A); parent directories are synced after publication and temporary removal. This is an atomic publication equivalent to rename with no replacement. Objects, then logical revision bindings, then event receipts are durably published. Receipt publication is the commit point. Directory sync errors refuse success even if the receipt became visible; exact retry verifies it. No automatic promotion of interrupted objects. Recovery reports unfinished temporaries, orphan objects/bindings, missing/corrupt objects, binding loss, event gaps and chain mismatch. Unresolved recovery findings block writes. Index files are not authority and may be deleted/rebuilt from receipts.

Implementation details, acceptance evidence and the focused continuation audit follow below.

## Implemented interfaces and wire layouts

[model.go](../../internal/corpus/model.go) pins every field's name, type and declaration order. `Object` has the common envelope followed by an explicit nullable tagged union: policy, candidate, relations, assignments, exposure, safe attempt, manifest or notice. Exactly one matching payload is required. `Event` pins sequence, previous digest, operation ID, request digest, action, output identity, producer and reported time. Exposure identity/context/category live in the referenced immutable object; its receipt supplies sequence and previous digest. Neither contains its own digest. Policy objects bind the code-owned vocabulary digest; other objects bind an earlier registered policy, except safe refusals without a resolvable policy, which bind the vocabulary anchor. Manifest receipts bind the manifest, which binds the preceding ledger head.

All object set arrays are sorted, with empty sets encoded as `[]`; unused union arms and absent parent digests use `null`. References sort by ID; citations by citation ID; captures by citation ID/record digest; relations by relation ID; assignments by candidate ID; budgets by family; targets/counts/deficits by name; closure digests by hex. Fact bases, reason codes, aliases, categories and other string sets sort by Go bytewise string order. Ordered event/revision history is not sorted. Strings are limited to 4096 UTF-8 bytes. Revisions/sequences use `uint32` with an additional 65535 ceiling; counts derive from bounded inventory. No floating point, numeric confidence, URL normalization, implicit timestamp, locale ordering or random selection enters identities. The vocabulary accessor returns a copy.

[Attempt golden bytes](../../internal/corpus/testdata/attempt.golden.json), their [independently calculated SHA-256](../../internal/corpus/testdata/attempt.sha256), and the [complete wire fixture](../../internal/corpus/testdata/wire.golden.json) pin records, manifests and receipts. These fixtures intentionally contain no final newline. Changes require explicit wire-profile review, not automatic test regeneration.

The library exposes `Encode`, `Decode`, `DecodeRequest`, `Store.Apply`, `PrepareFreeze`, `Head`, `Recover`, `Inspect`, `Verify` and `RebuildIndex`. CLI usage:

```text
failuremesh corpus policy register --store ROOT --input REQUEST.json
failuremesh corpus candidate add|revise|exclude --store ROOT --input REQUEST.json
failuremesh corpus cluster --store ROOT --input REQUEST.json
failuremesh corpus assign-family --store ROOT --input REQUEST.json
failuremesh corpus assign-split --store ROOT --input REQUEST.json
failuremesh corpus exposure append --store ROOT --input REQUEST.json
failuremesh corpus freeze --prepare --store ROOT --input REQUEST.json
failuremesh corpus freeze --store ROOT --input PREPARED.json
failuremesh corpus verify --store ROOT --digest HEX --head HEX --at UTC [--historical]
failuremesh corpus inspect --store ROOT --digest HEX
failuremesh corpus retire|withdraw --store ROOT --input REQUEST.json
failuremesh corpus head|recover --store ROOT
failuremesh corpus index rebuild --store ROOT
```

`REQUEST.json` is the exact no-newline `Request` encoding: `operation_id`, `expected_head`, `action`, `object`. `freeze --prepare` emits that same directly reusable format without publishing. Other CLI results are newline-framed JSON for terminal use, not hashed objects. Candidate mutations supply a complete next revision. `assign-family` changes a candidate hypothesis through that same validation path. `attempt` also accepts an explicitly prepared minimal failure envelope. Exit codes are 0 completed, 2 malformed/integrity/version, 3 policy/lifecycle, 4 I/O/stale head. A safe refusal emits its audit receipt while preserving the refusal exit class (2, 3 or 4); it is never a successful domain operation. SHORTFALL freezes exit 0.

Captured evidence requires `--evidence-store ROOT --evidence-store-id ID`; repeat `--parent-file FILE` for explicitly permitted transient parents. Parent files are regular, bounded local inputs, limited to 4 MiB each and 64 MiB total. There is no URL-fetch, source-body export or automatic evidence creation command. All identities and times are supplied; chronology remains SELF_REPORTED.

## Intake, clustering, exposure and allocation

Candidate revisions bind discovery, exact citation metadata, optional captured identities, publisher aliases, project lineage, separately typed dates, system/stack context, selection vectors, family hypotheses, origin/episode/independence declarations, rights/availability, decisions, split snapshots and synthetic ancestry. Unknown facts carry a reason and null value. Citation-only entries never acquire invented content digests. Refused submissions retain an opaque operation-derived attempt identity and safe administrative reason, excluding candidate IDs, citations, payload bytes and payload digests. Marker detection reuses Phase 2A; it is not a general classifier for confidential prose. Operators must submit metadata, not disguise source text as rationale.

Origin components collapse established incident/episode/derivative relations and identical citation locators. Possible overlap defers natural counts and joins allocation components. QUOTES_ORIGIN leaves incident counts separate but conservatively joins allocation dependence. Project identity, historical origin/project aliases and synthetic ancestry broaden allocation components. Directed ancestry cycles and dangling exact revisions are refused. Rejected proposals remain stored. Synthetic descendants never add natural cases, even if their input label claims otherwise. Representatives are the first eligible candidate in sorted ID order, one per origin. Family labels remain tentative; EVIDENCE_SUPPORTED is refused without calling a matcher or evidence assessor.

Publisher names and declared groups are conservatively joined through historical aliases, using lowercase plus surrounding-whitespace removal for publisher grouping only. Raw names remain in candidate records. Unknown publishers cannot establish diversity. The default three-times-group-count cap is enforced at freeze unless a registered pre-result exception exists; such an exception permanently displays DIVERSITY_SHORTFALL. Counts include origins, publishers, projects, stacks, tentative families, decisions/reasons, duplicates, synthetic/unresolved entries, audit tiers and splits. Deficits retain the approved 25/5-per-family/15–5–5 targets and 3–1–1 family/split targets even when a smaller search budget is supplied. Missing declared challenge categories also produce deficits; easier families cannot fill them.

Exposure is unioned across every historical revision and current dependency component, every recorded actor/context/model, and both actual and available access. Missing declarations are UNKNOWN; YES dominates UNKNOWN and NO_WITH_BASIS. Changing model, round, name or revision cannot clear recorded ancestry. Model pretraining always remains UNKNOWN. The manifest contains both the actor/context matrix and component-effective exposure. Claims depend on declared context and attribution: the tool cannot discover concealed aliases, unreported access or false source metadata.

Explicit assignment tables allocate whole components. Development cannot become fresh validation/holdout; validation cannot become fresh holdout. Revealed holdouts may become development/regression material in a successor manifest, while historical membership and exposure remain. Late component merges append their relation receipt; current verification reports contamination against affected old freezes without editing those manifests. V1 conservatively retains all historical established/possible dependencies. It does not implement an operation to erase an erroneous dependency or restore freshness.

## Freeze, audit, inspection and recovery

Closed inventory contains every current candidate and safe failed-attempt identity in the register, with all earlier revisions in the closure. Pending candidates, omitted exclusions/attempts, partial assignment tables, false summaries, stale policy/assignment references and invalid parent manifests are refused. `PrepareFreeze` computes a reviewable manifest; `Apply` repeats structural, closure, current rights and Phase 2A checks under the lock before publishing. Frozen candidate membership is derived from receipts, not a circular candidate field. DRAFT/SELECTED are revision-local; FROZEN, later exposure and retirement are derived from immutable ledger history.

The corpus capsule itself supports REGISTER_ONLY for uncaptured citations and CONDITIONAL_AUDIT for captured references whose bytes remain outside the capsule. Historical summaries are recomputed from those references, never from an old saved “verified” flag. Current verification separately reruns Phase 2A validation and reports LOCAL_AUDIT_AVAILABLE only when permitted local pinned bytes are currently available. It acquires the evidence store's cooperating lock, verifies exact artifact/revision bindings and validates cumulative retained-artifact coverage using an existing real record's claims. No AtomicClaim is synthesized for corpus intake. Parent loss, forged ranges and complementary excerpts remain blocked. Audit loss does not erase historical manifest integrity. Explicit withdrawal/retirement notices block current use while preserving bytes.

Verification separately emits `integrity`, `selection_target_status`, `current_use_status`, `audit_capability`, `freshness`, `chronology_tier` and pretraining UNKNOWN, plus historical/current summaries and later notices. Current mode requires the actual current head; historical mode requires a retained head at or after the receipt and makes no current-use claim. Inspection exposes metadata, revisions, decisions, exclusions and later notices without source expansion. The index is a disposable head-keyed inventory snapshot and is never read as authority.

The root is created mode 0700; pre-existing roots must have no group/other permission bits. Files are mode 0600. `O_NOFOLLOW` and regular-file checks protect object/input reads, and every configured directory ancestor is checked for symlinks. IDs are hashed for binding filenames and never interpolated into paths. Filesystem administrators and ancestors remain trusted against concurrent replacement. tmpfs is process-crash durable only, not power-loss persistent; overlayfs depends on its underlying mount. File/directory sync success cannot certify a storage device's power-loss behavior. Known unsupported filesystem types fail closed.

Recovery never deletes or promotes orphan objects. A caller may explicitly retry the exact interrupted operation: it is fully revalidated and may complete only its own matching orphan object/binding. Other orphans and unfinished temporary publications block writes and require local reconciliation; there is no automatic cleanup command. A missing interior event, chain mismatch, corrupt object, missing binding or incomplete committed closure refuses verification. Tail rollback requires a separately retained expected head to detect; an administrator can rewrite an unanchored store. An error after receipt publication but before successful directory sync is an uncertain acknowledgment, resolved only by a checked retry. No independent custody or chronology is claimed.

### B3 persistence and safe-envelope details

The existing receipt remains the commit point. Before publishing a refusal object/binding/receipt, the writer durably publishes `pending-refusal.json`, containing only the canonical safe attempt Request. Recovery exposes that path as unregistered state; Head, freeze and verification fail closed until an explicit retry resolves it. Other writers cannot bypass it. Retry completes the same opaque refusal; after the audit receipt is durable, the marker is removed and the root directory synced. Crashes after the marker, object, binding or receipt are exercised. No startup path promotes a pending attempt automatically. An unfinished exclusive-write temporary file still requires explicit local reconciliation.

Refusal envelopes contain a code, an `EXIT_2`/`EXIT_3`/`EXIT_4` reason tag, fixed tool/actor identity, fixed administrative rationale, and a registered policy digest/timestamp. If no policy resolves, they use the vocabulary digest and the explicit administrative epoch `1970-01-01T00:00:00Z`; this is not an occurrence-time claim. No submitted candidate ID, URL, rationale, body, source digest or rejected-payload digest is retained. Operation IDs must be safe opaque administrative identities. If the envelope has no usable ID, a new anonymous identity is derived solely from the existing ledger head and next sequence. Anonymous calls are distinct attempts; callers needing replay idempotence supply a stable opaque ID (`--attempt-id` for unreadable CLI envelopes). Reusing a refused operation returns its original refusal; conflicting reuse of a successful operation preserves the success and records a separate deterministic protocol-refusal identity without hashing the rejected payload.

A failure receipt is not a freeze receipt. Malformed/prohibited domain operations still exit with their original refusal class. Read-only decoding/preparation is not submission: `DecodeRequest` stays pure; callers submit via `Apply` or `ApplyBytes`. Failures to access the trusted root or read an input file cannot establish that a submission was registered. I/O/durability failure is reported, never represented as an acknowledged attempt. A persisted pending marker/orphan blocks freezing; a wholly unwritable filesystem cannot provide a durable acknowledgment or a persistent marker. Existing administrator/trusted-filesystem limitations apply.

The pending record is covered by the same regular-file, symlink, object-size, exclusive-publication and directory-sync protections, and counts toward aggregate store limits. No limits were increased. The [new refusal golden fixture](../../internal/corpus/testdata/refusal.golden.json) pins pending Request, safe object and receipt bytes; its SHA-256 is `13f3b63e9951e6a482598ab33d086b0b190409905ccfd5b8eed894a90998b480`. Existing object and manifest field layouts and original golden fixtures remain unchanged. Assignment binding deliberately reuses the receipt prefix instead of introducing independently editable duplicate revision/component fields. Reassignment after any candidate/dependency/exposure change is conservative across the local register, including changes that later prove unrelated.

Only B1–B4 and directly adjacent exposure, refusal-publication and assignment-consistency defects were corrected. No real incident corpus, crawler, later-phase machinery or new execution authority was added. Governance remains the checkpoint above.
