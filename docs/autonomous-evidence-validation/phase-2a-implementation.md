# Phase 2A — source provenance and atomic evidence claims

Status: implemented for independent implementation review under the owner's explicit Phase 2A task authorization. This is the first bounded implementation of the [foundation](phase-1-foundation.md), subordinate to the [baseline](../company/canonical-baseline-v1.0.md). It does not authorize later roadmap stages or change the approved architecture.

## Implemented surface

The focused [internal/evidence package](../../internal/evidence) provides manually supplied source capture, exact evidence locations, candidate claims, deterministic structural assessments, and inspectable content-addressed local JSON records. It has no network, process execution, database, service, CLI integration or legacy matcher integration. Existing PFC and historical verifier formats remain unchanged.

- `SourceArtifact` v1 separates logical source ID, immutable artifact ID/revision and exact content digest. It records supersession, URLs, attributed publisher and publication basis, retrieval provenance/time, quality dimensions and policy, rights, retained bytes/locations, availability/check time, mutability, origin/mirror/archive/revision relations and sensitivity. Publication time can be absent with an explicit basis. URLs are locators; query strings, fragments and user information are refused in this sanitized metadata profile.
- `Capture` hashes the exact supplied bytes using SHA-256. It never normalizes line endings or acquires content. Whole-body retention requires both the caller's explicit `retain` argument and an `allow` policy. Metadata-only captures keep no body. The caller supplies source metadata; this is not attested acquisition.
- Locations bind a unique ID, artifact identity/digest, selector representation, optional excerpt/digest, sensitivity and replay limitation. V1 resolves half-open byte ranges. Line/page/section selectors are representable citations, explicitly unavailable for local byte replay. Missing retained bytes cannot be labeled accessible. Excerpts require explicit permission and scope. Retained excerpts must be bound to exact parent bytes: the parent hash must match the content digest, declared length must equal actual length, bounds must be valid, and excerpt bytes must equal the selected parent slice. Parent bytes may be retained under whole-body permission or supplied transiently to validation; a complete excerpt whose hash equals the parent digest is itself a verifiable parent, still subject to whole-body rights. Without those bytes, partial excerpt retention/export fails closed. This does not expand the synthetic predicate rule's semantic coverage. Full-body coverage, including excerpts across captures/revisions sharing the same tagged content digest, still requires explicit whole-body retention permission from every byte-contributing capture. Alias/source IDs do not separate that coverage boundary; overlap and duplicates contribute only their unique covered ranges.
- `AtomicClaim` v1 carries a revision, predicate, typed boolean/string/unknown candidate value, subject and exact scope, epistemic basis, source and location refs, extraction/proposer/model/prompt/input identities, optional advisory confidence, freshness, privacy boundary, derivation and candidate support/conflict metadata. Unknown values require a reason. Claim assessments are separate immutable objects, bound to the full input record digest and target revision; supplied candidate status is never authoritative.
- Scope includes build, configuration, environment, run, operation, identity domain and the supported quantifier `one_bounded_operation`. Wider quantifiers are not implemented. Derivation references/digests are checked for integrity and cycles; no derivation inference rule is implemented.

## Effective states and assessment ordering

| Effective state | Meaning in this implementation | Projection |
| --- | --- | --- |
| `SUPPORTED_TRUE` | Current admissible structured synthetic positive evidence in the exact scope | `TRUE` |
| `SUPPORTED_FALSE` | Current admissible structured synthetic negative evidence with bounded observer completeness | `FALSE` |
| `UNKNOWN` | Missing candidate value or unresolved interpretation/completeness | `UNKNOWN` |
| `CONFLICTING` | Current admissible positive and negative evidence in the same scope/basis | `UNKNOWN` |
| `STALE` | Otherwise sufficient evidence outside its explicit validity interval | `UNKNOWN` |
| `UNSUPPORTED` | Malformed/unresolvable input, unsupported predicate, quarantined input, absent admissible support or AI-only assertion | `UNKNOWN` |

`Assess` first validates the entire frozen input set, including references. Structural failures produce unsupported results. Before aggregating related claims, it checks the target against the registered predicate rule, including accepted value type and claim representation. An ineligible target returns `UNSUPPORTED` with its exact rejection reasons and projects to `UNKNOWN`; another valid claim can still be selected and assessed independently. For an eligible target it then inspects every supplied claim/location, determines materiality, freshness and predicate-specific admissibility, and selects the effective state. Current material conflicts take precedence over stale support. Otherwise current support is used, sufficient expired support is stale, and unresolved/unsupported mappings abstain. A current unresolved structured-fixture interpretation blocks certainty; an AI assertion without admissible underlying evidence cannot resolve a conflict or create an authoritative negative. For eligible targets, all structurally valid supports/challenges receive ordered accepted/rejected decisions and reasons, including out-of-scope, obsolete and non-evidentiary challenges. Malformed records are retained by the caller if needed; `Save` refuses them.

No majority vote, confidence threshold, source prestige or submitted `resolved` status reconciles a contradiction. Candidate values cannot override observations: disagreement is recorded and the rule-derived proposition determines the result. A source revision's supersession link alone is not a semantic correction rule. The evaluator only knows the supplied frozen evidence set; it cannot detect withheld outside evidence.

## Exact predicate coverage

There is **one** code-owned registered rule: `synthetic.same_operation_retry`, rule `synthetic-retry-v1`, policy `structural-v1`.

The rule reads canonical structured fixture bytes with exact subject/scope/freshness, the fixture observer identity `synthetic-complete-attempts-v1`, the completeness declaration `complete_bounded_operation`, and a list of operation identities. At least one initial attempt is required. Two or more attempts for the scoped identity support true; exactly one supports false. An unrelated identity does not count as a retry. Missing identity, absent initial attempt or missing completeness abstains. The source must be explicitly synthetic, attributed to the versioned fixture author, have the expected structured quality dimensions and tool provenance, and use `experiment_observed` in `synthetic-reference` scope.

These are manually authored structural fixtures. They do **not** prove that a real observer ran, that an arbitrary completeness declaration is true, or that a real incident occurred. The rule deliberately uses a synthetic predicate namespace. In particular, the existing `same_operation_retry` predicate is **unsupported** here; the new package cannot promote facts into the existing matcher. Supporting real traces or prose requires separately reviewed rules and observer/admissibility evidence.

AI can propose a candidate or extract from independently supplied structured fixture bytes, with model/prompt/proposer metadata preserved. Only the rule's admissible underlying bytes can establish a result. AI-generated source observations, AI-only claims, repeated AI agreement, high confidence, citations, human approval and official-source labels cannot create authority. Official documentation does not establish deployed runtime behavior; no natural documented-design predicate rule is implemented either. Source quality remains a seven-dimensional vector, not a ranking.

Freshness supports `pinned-build-v1` with no invented TTL, and `explicit-interval-v1` with a half-open validity interval. Evaluation time is recorded, never taken from the ambient clock. Old pinned observations remain valid for that old build; changing a claim's build does not change its source evidence. Observation freshness is read from the bound fixture, so changing candidate freshness cannot extend it. `Revalidate` produces a new input record at the supplied time; it does not reacquire sources or renew expired evidence.

## Rights, privacy and local storage

Rights separately model metadata, digest, excerpt, whole-body and export policy as `allow`, `deny` or `unknown`, with license/basis/review, explicit excerpt scope and optional retention deadline. This is policy state, not a legal conclusion. Metadata/digest retention must be explicitly allowed for records admitted here. Unknown export permission always blocks redistribution, including when local body retention was allowed.

`Export` returns bytes only when every included artifact is export-permitted, classifications are public/synthetic, retention is valid at the explicitly supplied check time, and caller approval binds the exact record digest and destination. It sends nothing. There is no silent redaction or automatic export derivative. `Save` also checks the supplied retention-check time and combines candidate coverage with all persisted artifact bindings in the same store before publishing candidate bytes. A store-wide OS file lock serializes that read/check/publish boundary across cooperating saves. Prior excerpts are reverified against parent bytes under that same lock; stored coordinates, IDs and excerpt digests are not proof of their parent position. Orphaned artifact bindings still contribute coverage; unreadable bindings or interrupted temporary publications fail closed pending local review. Applications must supply an honest current policy-check time. The stateless `Export` API validates cumulative coverage across the complete record being exported, plus every contributor's export permission. It has no release-history ledger: separate export calls or independent store roots are not combined automatically. Callers must present the complete intended export composition; this correction adds no export service or cross-store registry. There is no scheduler to delete expired files, rights-revocation feed or access-control service; the owner must enforce deletion/withdrawal outside this library. Historical decoding/assessment can inspect a frozen record, and must not be interpreted as permission to retain or redistribute it today.

Explicit `[PRIVATE]`, `[SECRET]`, `api_key=`, `password=` and private-key markers are classified/quarantined; unknown sensitivity stays unknown. Metadata and raw byte payloads receive separate checks, including base64-encoded payloads on export. This marker policy is a bounded test mechanism, **not general PII/secret detection**. Classification and collector identities supplied by a caller are not authenticated. Source instructions are inert bytes: there is no command evaluation, LLM call, telemetry, prompt dispatch or automatic replay-script execution.

`Encode`/`Decode` pin `evidence-v1`, `structural-v1` and `go-json-v1`: exact UTF-8 Go `json.Marshal` bytes, deterministic struct/key ordering, no trailing newline, array order preserved, finite numbers, explicit field representation and a 4 MiB record limit. Readers verify the tagged SHA-256 digest first, reject unknown fields, then require exact re-encoding equality. This intentionally rejects duplicate keys, omitted-field aliases, casing variants, alternate escapes/numbers, trailing bytes and other ambiguous/non-profile representations. It is not a cross-language canonicalization standard. Raw source bytes remain independently hashed before JSON/base64 encoding.

`Save` writes content-addressed input and assessment JSON objects, plus immutable local bindings for artifact IDs, source revisions and claim revisions. Different bytes cannot replace an existing binding through this API. New source captures and changed claims require new revisions. Publication uses an exclusive atomic hard link from a synced temporary file; concurrent identical writes are idempotent. Multi-object saving is not a transaction: interruption may leave valid unreferenced objects/bindings, and retrying the same input is safe. Optional `parents ...[]byte` arguments to `Validate`, `Encode`, `Decode`, `Save`, `Read`, `Export` and `Assess` supply transient verification bytes only. The shared verifier indexes parents by their computed SHA-256, checks actual length and exact slices, then performs interval union. `Capture` checks its supplied original bytes directly. These arguments are never serialized or published, and source/claim record encoding is unchanged. When a parent is not retained, callers must resupply it on subsequent validation, export or replay, and for all persisted partial-excerpt bindings inspected by `Save`. Missing parents fail closed even if the original save verified them; no persisted caller-controlled "verified" flag is trusted. Metadata/digest-only records remain usable without parent bodies because they retain no text ranges.

The root directory must be trusted, locally controlled and on a filesystem supporting hard links and POSIX `flock` (tested on Linux); this is not an adversarial multi-user filesystem sandbox. Object symlinks are refused. Administrators can still replace/delete storage; no write-once storage, attestation, authenticity, independent chronology or truth is inferred from a digest.

These are implementation regressions, not independent external validation or a corpus.

## Independent-review blocker correction — B1 and B2

The independent implementation review returned REVISE with two blocking defects. Both were reproduced before correction using [blocker regressions](../../internal/evidence/blockers_test.go): complementary half-body excerpts across revisions passed `Validate`, `Save`, `Export` and successive saves despite whole-body denial; a string-valued target inherited `SUPPORTED_TRUE` from a valid related boolean claim despite its own type rejection.

B1 now aggregates retained intervals by exact tagged content digest within a record and across persisted captures in one store. Inconsistent length/representation for one digest is rejected. Coverage requires explicit whole-body permission from every byte-contributing capture; one alias's permission does not override another's deny/unknown policy, and metadata-only permission cannot grant authority over retained text. Adjacent ranges merge, overlaps/duplicates add no extra coverage, gaps remain gaps, and invalid/zero-length selectors are rejected. B2 validates the target's registered predicate/type/representation eligibility before any support or conflict aggregation. It preserves the precise rejection reason and leaves valid related claims independently assessable.

Regression coverage includes both original exploits, complementary thirds across successive saves, aliases, revisions, out-of-order/overlapping/duplicate/gapped ranges, explicit permissions and export refusal, concurrent saves, orphaned/unreadable persisted bindings, invalid target types with repeated or contradictory support, AI/human/tool proposers, valid cross-claim positive/negative support and preserved conflict handling. These corrections do not expand predicate coverage, change governance, or add corpus/execution capabilities. Final re-review remains pending.

## Final B1 parent-binding correction — 2026-09-17

Final independent re-review confirmed B2 closed but returned REVISE for forged parent/range/length metadata. The previous cumulative union was correct only if its coordinates and denominator were truthful; an excerpt digest did not establish either. A separate temporary Go program using the public package API, its own records and the exact parent `abcdefghijkl` reproduced both attacks before correction: `abcdef` plus `ghijkl`, both labeled `[0,6)`, and correct half ranges with declared length 13. `Validate`, both successive saves and complete-record `Export` all succeeded in both cases.

The shared coverage verifier now requires exact parent-byte binding before admitting any excerpt interval. With the parent supplied, the first attack returns `excerpt_parent_slice_mismatch`; the second returns `parent_length_mismatch`. Without the parent, both return `excerpt_parent_unavailable`, including export with zero returned bytes. The independent probe also confirms valid `[0,3)` plus `[6,9)` succeeds with the true parent, while a wrong parent digest is refused. No transient parent body is added to stored/exported records. No general cryptographic proof format or new acquisition path is introduced.

[Parent-binding regressions](../../internal/evidence/parent_binding_test.go) cover the exact attacks, invalid/zero/negative/out-of-bounds ranges, true excerpt digests at false positions, wrong parent digest/length/relationship, retained and transient parents, verified partial/gapped/overlapping/duplicate coverage, prohibited versus explicitly permitted complete coverage, unavailable-parent replay, successive captures with distinct IDs/sources, and forged prior persisted bindings. Existing B1 interval, lock/concurrency, orphan/corruption tests now supply their real parent bytes rather than treating unverified coordinates as authoritative. B2 implementation is unchanged except for forwarding optional verification bytes to `Validate`; its eligibility and projection regressions remain mandatory.

Limitation: Phase 2A has no persistent proof of partial-excerpt membership in an unavailable parent. Therefore excerpt-only records require permitted access to the parent again for validation/replay/export; loss of that access causes refusal, not an inferred safe partial range. Whole-body permission alone does not certify an excerpt's position. The existing one-store persistence and one-complete-record export boundaries remain; there is no cross-store or cross-release ledger. Governance and all excluded capabilities remain unchanged.
