# Instructions for coding agents

Read [the canonical baseline](docs/company/canonical-baseline-v1.0.md), [invariants](docs/invariants.md), [system architecture](docs/architecture/system.md), and [HANDOFF.md](HANDOFF.md) before making changes. Repository docs are authoritative within their scope; the canonical baseline takes precedence if another document conflicts. Do not silently redesign architecture. A thesis change must be reported as **PROPOSED BASELINE CHANGE** with the baseline's required rationale and evidence, not edited into the baseline.

Before every implementation or review session, inspect `git branch --show-current`, `git status --short`, `git ls-files --others --exclude-standard`, and `git diff`. Ordinary `git diff` excludes untracked files. Inspect every untracked file explicitly before any authorized staging. After authorized staging, run `git diff --cached --check`, `git diff --cached --stat`, `git diff --cached --name-status`, and `git status --short`, and explicitly inspect the complete staged patch with `git diff --cached`. Before commit, run `git grep --cached -nEi '(password|passwd|secret|api[_-]?key|access[_-]?key|private[_-]?key|token)' -- ':!go.sum' || true` and review every match; neither matches nor zero matches alone establish whether secrets are present. Run the phase-appropriate final quality gates before commit. A commit may proceed only after the complete staged patch and secret-scan matches are reviewed, staged diff checks are clean, and required local quality gates are complete. A clean ordinary diff or staged stat/name-status/check alone never authorizes a commit. Preserve existing user work. Work only within the current phase in HANDOFF.md and the phase document. Maintain the privacy boundary, evidence integrity, safety gates, three-state applicability, and scoped execution verdicts. Distinguish requirements and observed evidence from assumptions and hypotheses. Keep LLM output advisory; verifier logic and recorded evidence determine verdicts.

Run tests and required checks appropriate to each change. For Phase 0 run `gofmt -l .`, `go vet ./...`, `go test ./...`, `go mod verify`, and `git diff --check`; report honestly when there are no Go packages or tests. Update HANDOFF.md when phase work changes. Never commit or push unless explicitly instructed. Never stage unless explicitly instructed. Do not implement later phases while completing the current one.
